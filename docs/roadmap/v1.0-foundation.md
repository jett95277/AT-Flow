# V1.0 Foundation

## Status

Completed.

## Mission

V1.0 builds the foundational AT Flow runtime: a CLI-first multi-agent orchestration shell with explicit state, agent boundaries, artifact handoff, trace, audit, and retry behavior.

The goal of this version is not to prove a polished product interface. The goal is to prove that multiple agents can be coordinated by a platform-owned runtime instead of sharing one uncontrolled conversation context.

## Owns

- CLI entry through `at.py` and `python -m at_flow`.
- Workspace initialization through `at.config.json` and `.at/`.
- Four-agent serial pipeline: `main -> analysis -> code -> test`.
- Session state stored in `.at/sessions/<session-id>/state.json`.
- Session lock to prevent two runners from advancing the same session at once.
- Per-agent package: `agent.md`, `permissions.json`, and `output.md`.
- Per-agent directories: `inbox`, `outbox`, and `workspace`.
- Artifact handoff from one agent to the next.
- Path-level permission audit.
- Structured failure artifact.
- Retry and interrupted-step recovery.
- `mock` provider for local closed-loop verification.
- Trace, audit, artifact, status, list, retry, and doctor CLI commands.

## Architecture Boundary

V1.0 establishes the core AT principle:

```text
Agent produces.
AT Flow governs.
```

The provider may generate content, but it does not own state transitions, handoff routing, permission decisions, or session recovery.

## Verification Gate

V1.0 is complete only when:

- a mock session can run through `main -> analysis -> code -> test`;
- each agent receives its own package and private workspace;
- prior artifacts are routed into the next agent inbox;
- forbidden writes to shared files or other agent directories are detected;
- provider failure creates a visible failure artifact;
- interrupted running steps are recovered as retryable failures;
- tests cover the runtime contracts and sandbox behavior.

## Does Not Own

- Web Console.
- Cloud deployment.
- Codex provider stability.
- opencode provider stability.
- Full production sandboxing.
- Parallel or DAG-based multi-agent execution.
- Multi-user access control.

## Known Limits

- The isolation layer is path-audit based, not OS-level enforcement.
- The default pipeline is serial.
- `mock` is the reliable provider for tests; real code-agent providers require later hardening.
- Runtime state is local filesystem state, not a managed service.
