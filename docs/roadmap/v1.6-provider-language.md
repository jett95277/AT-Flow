# V1.6 Provider Language

## Status

Completed.

## Mission

V1.6 keeps both official AT usage modes while adding provider routing and language contract support.

The key decision is that AT Flow must not collapse into a simple `frontend -> backend -> GPT API` application. Codex, opencode, OpenAI API, and mock are provider routes behind the same AT runtime contract.

## Owns

- Per-agent provider routing through `agent_providers`.
- Session-level provider fallback.
- Provider resolution per agent step.
- Codex and opencode process-provider configuration.
- Preservation of Codex Conversation Mode.
- Preservation of Web Console Mode.
- Language contract file for sessions.
- Runtime/display language separation.
- Prompt language policy skill.

## Provider Boundary

Provider routing follows this principle:

```text
AT Flow owns orchestration.
Provider owns bounded execution.
```

The provider for a step may be `mock`, `codex`, `opencode`, or another supported provider. The selected provider receives a bounded prompt and environment. It returns output, while AT Flow collects artifacts, audits permissions, updates state, and routes handoff.

## Language Boundary

V1.6 introduces the idea that user-facing language and runtime prompt language can be different.

Recommended default:

```text
user input: Chinese
runtime prompt: English
display summary: Chinese
artifact mode: bilingual or policy-driven
```

Paths, commands, API names, file names, and code identifiers must not be translated.

## Verification Gate

V1.6 is complete only when:

- per-agent provider routing can override the session provider;
- engine execution resolves provider per step;
- Codex and opencode remain provider adapters, not flow owners;
- Codex conversation trigger keeps AT state before provider execution;
- Web Console can create sessions with explicit provider selection;
- language contract is written into the session and included in agent context;
- Python tests, frontend tests, frontend build, and Web API smoke checks pass.

## Does Not Own

- Stable non-interactive Codex execution across all environments.
- Stable opencode execution.
- Provider marketplace.
- Cloud deployment.
- OpenAI API as a replacement for Codex code-agent capability.

## Known Limits

- Codex/opencode process providers may require environment-specific authentication and command behavior.
- Language adaptation is contract-first and deterministic before model-assisted translation is introduced.
- Provider fallback must stay explicit; silent fallback between real providers is not allowed.
