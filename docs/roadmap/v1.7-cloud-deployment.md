# V1.7 Cloud Deployment

## Status

Current.

## Mission

V1.7 turns AT Flow from a local Web Console into a protected cloud demo that can be opened through a public HTTPS domain.

This version proves deployment, persistence, reverse proxying, and public demo reliability. It does not try to prove stable cloud execution for every external Code Agent provider.

## Owns

- React production build.
- FastAPI production runtime.
- Nginx reverse proxy.
- HTTPS setup.
- systemd backend service.
- SQLite and `.at` runtime data persistence.
- Basic Auth or equivalent minimal public access protection.
- Reproducible deployment documentation for a fresh Ubuntu server.

## Deployment Architecture

```text
Public user
  |
  | HTTPS :443
  v
Nginx
  |
  |-- /      -> React static build
  |
  |-- /api/  -> FastAPI backend on 127.0.0.1:8000
                    |
                    v
                 AT Runtime
                    |
                    |-- .at/sessions
                    |-- .at/shared
                    |-- .at/projects
                    |-- .at/web/console.sqlite3
```

FastAPI must bind to localhost. Port `8000` must not be publicly exposed.

## Default Provider

V1.7 cloud demo should default to:

```text
mock
```

The cloud demo must prove that the AT runtime, state machine, trace, audit, artifacts, file tree, and session flow work after deployment. Codex and opencode may be visible as configured providers, but they are not the V1.7 completion claim.

## Verification Gate

V1.7 is complete only when:

- `https://<domain>/` opens the Web Console;
- `https://<domain>/api/health` returns healthy backend state;
- a `mock` session can be created, stepped, continued, and inspected;
- trace, audit, artifact, and session state are visible from the Web Console;
- backend is managed by systemd and survives restart;
- runtime data persists after backend restart;
- port `8000` is not publicly exposed;
- public access is protected by at least HTTP Basic Auth.

## Does Not Own

- Stable cloud execution of Codex CLI.
- Stable cloud execution of opencode.
- GPT/OpenAI API as a replacement for Codex.
- Full authentication system.
- Multi-user or multi-tenant runtime.
- Docker or Kubernetes deployment.
- Managed database migration.

## Known Risks

- Real Codex CLI execution on a cloud server may require authentication, non-interactive command behavior, and stronger sandboxing.
- If no domain is available, HTTPS cannot be fully verified.
- Low-memory servers may need swap for frontend build.
- Incorrect Nginx or CORS configuration can make the frontend appear broken even when the backend is healthy.
