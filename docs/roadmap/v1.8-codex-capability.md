# V1.8 Codex Capability

## Status

Next.

## Mission

V1.8 makes AT Flow genuinely reuse mature Codex code-agent capability instead of merely calling a generic GPT/OpenAI API and treating it as equivalent.

Codex should become a reliable bounded provider for selected AT agent steps, especially `code` and `test`, while AT Flow continues to own state, context, permissions, handoff, trace, audit, and recovery.

## Owns

- Codex CLI availability detection.
- Codex authentication and environment diagnostics.
- Codex provider capability check.
- Non-interactive Codex execution contract.
- Clear provider failure artifacts when Codex cannot run.
- Runtime trace events for Codex provider lifecycle.
- Web Console visibility for Codex availability and failure state.
- Controlled Codex-backed execution for at least one supported agent step.

## Codex Boundary

Codex is a mature code-agent provider, not the AT flow owner.

Correct path:

```text
User
  -> AT Runtime
  -> bounded agent step
  -> Codex provider
  -> artifact / trace / audit / state
```

Incorrect path:

```text
User
  -> Codex owns the whole workflow
  -> AT only displays whatever Codex says
```

## OpenAI API Role

OpenAI API may be added as a supporting provider, but it must not replace Codex as the V1.8 primary code-agent capability.

Allowed supporting roles:

- translation
- summary
- lightweight analysis
- routing assistance
- language contract support

Not allowed as the V1.8 primary claim:

```text
Web input -> FastAPI -> GPT API -> pretend this is Codex-equivalent code-agent execution
```

## Verification Gate

V1.8 is complete only when:

- AT can detect whether Codex is available;
- AT can explain why Codex is unavailable;
- Codex execution failure is visible in session state, failure artifact, trace, and Web Console;
- at least one controlled Codex-backed agent step can run in a supported environment;
- `mock` remains available as the safe fallback for demos and tests;
- there is no silent fallback from Codex to another real provider.

## Does Not Own

- opencode first-class integration.
- Provider marketplace.
- Multi-provider benchmarking.
- Full plugin packaging.
- Cloud-hosted Codex authentication automation.

## Known Risks

- Codex CLI behavior may differ between local desktop, CI, and cloud server environments.
- Non-interactive execution may require explicit prompt mode and authentication handling.
- Codex may need access to local project context that must still respect AT context and permission contracts.
