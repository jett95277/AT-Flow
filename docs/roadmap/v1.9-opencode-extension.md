# V1.9 opencode Extension

## Status

Later.

## Mission

V1.9 makes opencode a first-class pluggable provider after the Codex provider contract is stable.

The goal is not to rewrite the AT runtime. The goal is to prove that another mature Code Agent can follow the same context, artifact, permission, trace, audit, and failure contracts without special-casing the state machine.

## Owns

- opencode provider capability check.
- opencode command contract.
- opencode execution diagnostics.
- Provider adapter contract cleanup.
- Web Console provider comparison visibility.
- Explicit provider selection among `mock`, `codex`, `opencode`, and OpenAI API where configured.
- Consistent failure reporting for unavailable or failed opencode execution.

## Provider Boundary

V1.9 should keep the same runtime boundary established by earlier versions:

```text
AT Runtime
  -> provider adapter
  -> opencode
  -> artifact / trace / audit / state
```

opencode must not bypass:

- `context.json`
- `permissions.json`
- private agent workspace
- artifact contract validation
- permission audit
- state transition rules

## Verification Gate

V1.9 is complete only when:

- opencode can be checked for availability;
- unavailable opencode state is explicit and observable;
- opencode provider execution follows the same context, artifact, trace, audit, and permission contract as Codex;
- provider selection remains explicit;
- no silent fallback from one real provider to another occurs;
- mock, Codex, and opencode can coexist without changing core state-machine logic.

## Does Not Own

- Reworking the V1.7 deployment topology.
- Replacing Codex provider semantics.
- Building a full plugin marketplace.
- Removing `mock` provider.
- Replacing the AT runtime with opencode-native workflow control.

## Known Risks

- opencode command-line behavior and authentication may differ from Codex.
- Provider capability checks must not accidentally run destructive project actions.
- Supporting multiple providers may expose inconsistent output formats unless artifact contracts remain strict.
